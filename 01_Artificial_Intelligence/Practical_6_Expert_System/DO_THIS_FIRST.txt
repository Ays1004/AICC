1. Open Terminal (Ctrl+Alt+T).
2. Find the pendrive name:

       ls /media/$USER

3. Go to the code folder (replace MYUSB):

       cd "/media/$USER/MYUSB/01_Artificial_Intelligence/Practical_6_Expert_System/code"

       python3 main.py

       yes     <- sneezing frequently?

       yes     <- forget things often?

       yes     <- pale skin?

HOW THE CODE WORKS (for viva)
-----------------------------
An expert system has three main parts:

1. Knowledge base
   The knowledge() function stores symptom -> disease rules:
       sneezes     -> Cold
       temperature -> Fever
       weakness    -> Iron Deficiency
       forgets     -> Alzheimer's
       cough       -> Covid-19
       paleness    -> Flu

2. Inference engine
   The doctor() function asks every question, stores the yes/no
   answers in a dictionary, then scans the knowledge base. For every
   symptom that is present, it adds the corresponding disease to the
   diagnosis list. This is forward chaining: facts (symptoms) are
   given, and rules produce conclusions (diseases).

3. User interface
   The ask() function is the text interface. It validates the answer
   and keeps asking until the user types yes or no.

This is a rule-based expert system. It does not learn; the rules are
written by a human expert.

Note: the repository's original question was "Are you able to
remember things clearly?" but YES added Alzheimer's, which is
backwards. This copy asks "Do you forget things often?" so YES
correctly means the symptom is present.


VIVA QUESTIONS AND SHORT ANSWERS
--------------------------------
Q1. What is an expert system?
A1. A computer application that uses a knowledge base and an
    inference engine to solve problems in a specific domain at the
    level of a human expert.

Q2. What are the components of an expert system?
A2. Knowledge base, inference engine, and user interface. Some books
    also list the explanation facility and knowledge acquisition
    module.

Q3. What is the knowledge base?
A3. A store of domain facts and IF-THEN rules. Here it is the
    symptom-to-disease dictionary.

Q4. What is the inference engine?
A4. The part that applies rules to the facts to derive conclusions.
    Here it scans the dictionary and collects matching diseases.

Q5. What is forward chaining?
A5. Data-driven reasoning: start with known facts and apply rules to
    derive new facts/conclusions. This program uses forward chaining.

Q6. What is backward chaining?
A6. Goal-driven reasoning: start with a goal and work backwards to
    find the facts that support it. Used in diagnosis systems that
    test hypotheses.

Q7. What is a rule-based system?
A7. A system whose knowledge is represented as IF condition THEN
    action/conclusion rules.

Q8. Difference between an expert system and a normal program?
A8. An expert system separates the knowledge base from the inference
    engine, so knowledge can be changed without rewriting the whole
    program. It also explains its reasoning.

Q9. What are the limitations of expert systems?
A9. Knowledge acquisition is difficult, maintenance is costly, they
    cannot handle novel situations outside their rules, and they do
    not learn automatically.

Q10. What is the role of the user interface?
A10. It lets a non-expert user answer questions and see the
     conclusion and explanation.

Q11. Why is a dictionary used for the knowledge base?
A11. It gives O(1) average lookup from symptom to disease and keeps
     the rules separate from the control logic.

Q12. How would you add a new disease?
A12. Add a symptom key and disease name to knowledge(), add the
     corresponding question to questions_list(), and the inference
     loop will handle it automatically.

Q13. What is the difference between the medical system and the stock
     alternative?
A13. The stock version uses the experta library and a forward-chaining
     rule engine with Fact and Rule classes. The medical version uses
     plain Python dictionaries and if/else logic.

Q14. What is experta?
A14. A Python rule engine library inspired by CLIPS. It lets you
     declare facts and rules with decorators. It may not install on
     every Python version.


COMMON MISTAKES
---------------
- Answering "y" or "n". The program expects "yes" or "no" (it will
  ask again).
- Expecting one disease only. The program can return several diseases
  if several symptoms are present.
- Using alternative_stock.py or alternative_airline.py without
  installing experta. Use main.py if pip fails.
- Forgetting that this is forward chaining, not backward chaining.
