Why jobs 4 and 3?
- Jobs sorted by profit: 40 (deadline 1), 30 (deadline 2),
  20 (deadline 1), 10 (deadline 2).
- Job 4 gets slot 1; job 3 gets slot 2.
- Jobs 2 and 1 cannot be scheduled because their deadlines are
  already filled.
- Total profit = 40 + 30 = 70.


HOW THE CODE WORKS (for viva)
-----------------------------
Selection Sort:
- Find the smallest element in the unsorted part of the list.
- Swap it with the first unsorted element.
- Move the boundary one position to the right.
- Repeat until the whole list is sorted.
- Time complexity: O(n^2) comparisons, O(1) extra space.
- It is not stable by default (the simple swap version shown here).

Job Scheduling (greedy with deadlines and profits):
- Each job takes one unit of time and has a deadline and profit.
- Sort jobs in decreasing order of profit.
- For each job, find the latest free time slot before its deadline.
- If a slot is free, schedule the job there and add its profit.
- This greedy choice is optimal for unit-time jobs with deadlines
  and profits.
- The slots array stores which job ID occupies each time slot.

Greedy strategy:
- Make the locally best choice at every step and never undo it.
- Greedy is not always optimal for every problem, but it is optimal
  for selection sort, Prim's MST, Dijkstra and this job-scheduling
  variant.


VIVA QUESTIONS AND SHORT ANSWERS
--------------------------------
Q1. What is a greedy algorithm?
A1. An algorithm that builds a solution step by step, choosing the
    best option available at each step, without backtracking.

Q2. Why is selection sort greedy?
A2. At each pass it selects the minimum remaining element and puts it
    in its final position. That is a locally optimal choice.

Q3. Time complexity of selection sort?
A3. O(n^2) in all cases (best, average, worst). Space is O(1).

Q4. Is selection sort stable?
A4. The simple swap version is not stable. Equal elements can change
    relative order.

Q5. What is the greedy criterion in job scheduling?
A5. Pick the job with the highest profit first, then place it in the
    latest available slot before its deadline.

Q6. Why process jobs by profit and not by deadline?
A6. Profit is the objective being maximized. Deadline only restricts
    where the job can be placed.

Q7. What is the time complexity of this job scheduling?
A7. Sorting is O(n log n); placing jobs can take O(n * max_deadline)
    in the simple implementation.

Q8. What is a Minimum Spanning Tree?
A8. A subset of edges that connects all vertices with minimum total
    edge weight and no cycles. Prim's and Kruskal's are greedy MST
    algorithms.

Q9. Difference between Prim's and Kruskal's?
A9. Prim's grows one tree from a starting vertex and adds the cheapest
    edge connecting the tree to a new vertex. Kruskal's sorts all
    edges and adds the cheapest edge that does not form a cycle.

Q10. Difference between greedy and dynamic programming?
A10. Greedy makes one irreversible local choice; DP explores
     subproblems and combines optimal solutions. Greedy is faster but
     is not correct for every problem.

Q11. Where is Dijkstra's algorithm used?
A11. Single-source shortest path on a weighted graph with
     non-negative edge weights. It is also greedy.

Q12. What does 999 mean in the Prim's code?
A12. It is used as "infinity" / no edge between two vertices. The
     code skips 999 entries.


COMMON MISTAKES
---------------
- Entering job ID, deadline and profit on one line. Enter one value
  per line.
- Using a deadline larger than the number of jobs; the slots array
  becomes bigger but still works.
- Confusing job ID with deadline. The order is ID, deadline, profit.
- In Prim's alternative, using 0 for "no edge". That code expects 999.
  (The simpler my_simple_prims_mst.py uses 0 instead.)
- Running selection sort twice in the original repository code mixes
  old and new numbers. This copy clears the list first.
